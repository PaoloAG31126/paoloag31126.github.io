Making your resume pass the ATS

A short, honest guide. No jargon, no hype — just what actually breaks and what doesn't.

Written by Vetro · ← Back to ClearCV builder

What an ATS actually is

An Applicant Tracking System (ATS) is the software a company uses to collect and sort job applications. When you upload a resume, the ATS does three things:

  1. Extracts the text from your file (PDF or .docx) using a text parser.
  2. Matches keywords against the job description to score or rank candidates.
  3. Passes a structured summary to the human recruiter.
The critical insight: the ATS reads the text layer of your file, not the visual layout. If the parser can't find your text, you get filtered out before a human ever sees your resume.

Things that commonly break ATS parsing

❌ Two-column layouts and tables

Most ATS parsers read top-to-bottom, left-to-right. A two-column layout causes text to be scrambled or dropped entirely. Single-column is safe. Table cells for layout are the #1 failure mode.

❌ Images, logos, and graphics for structure

Photos, company logos, skill bars, and icon rows are decorative. The parser ignores them. If you used a graphic to show "Figma 90%", the ATS sees nothing.

❌ Fancy or embedded fonts

Some ATS systems (especially older ones) strip non-standard fonts. Use system fonts: Arial, Calibri, Times New Roman, Helvetica, or a clean sans-serif available on Windows and macOS.

❌ Text inside images or headers/footers

Put your name, email, and contact info in the body of the document, not in the document header/footer area. Some parsers skip those regions.

❌ Unusual file formats

Submit as .docx or .pdf only. Avoid .pages, .odt, .tex, or image-based PDFs (a scanned PDF is just an image — no text layer).

The 10-second test: Open your resume PDF, select all the text, and paste it into a plain text editor (Notepad, TextEdit, or less on Linux). If the order is scrambled or sections are missing, an ATS will see the same problem.

Structure that works

Standard section headings

Use conventional names the ATS keyword matcher expects:

  • ✓ Experience / Work History / Employment
  • ✓ Education / Qualifications / Training
  • ✓ Skills / Core Competencies / Technical Skills
  • ✓ Summary / Profile / Professional Summary
  • ✗ "My Journey", "What I Bring", "The Good Stuff" (creative headings confuse keyword matching)

Dates in a simple format

Write them as a reader and parser both understand:

  • ✓ Jan 2021 – Present
  • ✓ March 2019 – August 2021
  • ✓ 2020 – 2023
  • ✗ A timeline graphic, a table with date columns, or "Year 3 of the team era"

Bullet points over paragraphs

Short action-verb bullets (Led, Built, Reduced, Improved) are easier for both the ATS parser and the human recruiter to scan. One achievement per line. Quantify where honest.

Keywords: match the job description

The ATS ranks applications by how well your resume matches the keywords in the job posting. This is not keyword stuffing — it means using the same vocabulary the job description uses.

Practical method: Open the job description. Underline or copy every skill, tool, certification, and responsibility mentioned. Make sure each one that applies to you appears somewhere in your resume — in the Skills section or in a bullet point.
  • Job says "Python, pandas, data cleaning" → include those exact terms if you use them.
  • Job says "stakeholder management" → use that phrase, not just "worked with clients".
  • Job says "CI/CD pipelines" → write "CI/CD pipelines", not "build and deploy processes".

You don't need every single keyword. You need the ones that apply to you, in the words the posting uses.

Before you hit Apply

  1. Copy-paste test: Select all text from your PDF, paste into Notepad. Read the result top to bottom. If it looks like your resume, you're fine. If it looks like a jumble, fix the layout.
  2. Check the file format: If the job says "PDF preferred", submit a PDF. If it says "any format", submit both — one in the upload box, one attached.
  3. Remove irrelevant experience: 20 years of work history dilutes keyword density. Keep the last 10–15 years unless the job asks for more.
  4. Save the file clearly: FirstName_LastName_Resume.pdf is better than resume_final_v2_(1).pdf.

Common myths

🚫 "ATS scores my resume out of 100 and rejects me below a threshold"

Most modern ATS systems don't do a single numeric score. They extract, match, and pass to a human. The "80% match score" you see in some tools is that tool's own formula, not the ATS.

🚫 "AI-written resumes get flagged and rejected"

No ATS is specifically trained to detect AI-generated text. However, generic AI phrasing ("dynamic, results-driven professional") stands out negatively to human readers. The risk is human, not automated.

🚫 "I need to use a specific ATS-optimized template"

A clean single-column layout with standard headings is ATS-compatible. You don't need to buy a template. Free tools that produce clean PDFs (like ClearCV) work fine.

🚫 "A fancy design helps me stand out"

Fancy design is invisible to the ATS and can break parsing. The resume you submit to the ATS is not the same one a hiring manager reads in a design portfolio context. Keep it clean.

Quick checklist — run this before every application

  1. Single column, no tables for layout?
  2. Standard section headings (Experience, Education, Skills)?
  3. Keywords from the job description present in my resume?
  4. Dates in a simple, readable format?
  5. Copy-paste into Notepad looks correct?
  6. File is .pdf or .docx, clearly named?
  7. No text hidden in images, headers, or footers?
If all seven are yes, your resume is ATS-safe. The next step is making it good to a human — which is a different (and harder) problem.
